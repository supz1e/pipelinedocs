Pangenome Assembly Pipeline

A full end-to-end Nextflow DSL2 pipeline for short-read pangenome discovery. Covers read QC, reference alignment, unmapped read extraction, de novo assembly, contamination screening, repeat annotation, gene prediction, gene filtering, pangenome construction, and presence/absence variation (PAV) analysis across a multi-sample cohort.

Overview

This pipeline takes paired-end Illumina reads from multiple accessions, aligns them to a reference genome, and extracts everything that did not align. Those unmapped reads are assembled de novo, cleaned of contamination, repeat-annotated, and fed into gene prediction. The resulting gene models are filtered for quality and novelty, then combined with reference genes to build a pan-gene catalogue. Finally, raw reads from every sample are aligned back to the pan-gene set to produce a presence/absence variation (PAV) matrix characterising the accessory genome.

Pipeline phases

Phase 1 — QC and alignment

FastQC-> MultiQC-> BWA index-> BWA align + sort-> Align stats-> Qualimap

Phase 2 — Assembly

Extract unmapped-> Convert to FASTQ-> Pool reads-> MaSuRCA assembly

Phase 3 — Contamination removal (BLAST path or FCS-GX path)

BLAST NT-> Filter BLAST-> Remove contaminants OR FCS-GX screen-> FCS-GX clean

Phase 4 — Repeat annotation

EDTA annotate and/or RepeatMasker-> Pangenome merge

Phase 5 — Gene prediction and filtering

BRAKER3-> CD-HIT filter-> Repeat-gene filter-> Extract filtered genes-> Ref similarity filter-> Build pan-gene set

Phase 6 — PAV analysis

PAV align-> PAV call-> PAV classify

2. Prepare the reference folder

Create reference/ at the pipeline root. Place exactly one genome FASTA (.fasta or .fa) and the reference coding sequence file — which must be named exactly cds_from_genomic.fna — inside it:

reference/
├── genome.fasta              <-- any name; .fasta or .fa only
└── cds_from_genomic.fna      <-- required; exact filename
Both files are mandatory. The pipeline exits at startup if either is missing or if more than one .fasta/.fa file is present.

3. Prepare protein hints for BRAKER

Create protein_hints/ at the pipeline root with exactly one protein FASTA file (accepted extensions: .fa, .fasta, .faa, .pep):

protein_hints/
└── proteins.fa

4. Configure FCS-GX (if using the FCS contamination path)

FCS-GX requires a local copy of the NCBI GX database. Once downloaded, open modules/fcs_screen.nf and update the two inline variables near the top of the script block:

GXDB_DIR="/path/to/gxdb"   # directory containing all.gxi, all.gxs etc.
TAXID=3827                 # NCBI taxid of your target organism

5. Organise samples

Create samples/ with one subdirectory per accession containing paired gzipped FASTQ files. Both naming conventions are accepted:

samples/
├── accession_A/
│   ├── accession_A_R1.fastq.gz   <-- R1/R2 style
│   └── accession_A_R2.fastq.gz
└── accession_B/
    ├── accession_B_1.fastq.gz    <-- 1/2 style
    └── accession_B_2.fastq.gz
Files must end in .fastq.gz. Any other suffix (e.g. _R1_001.fastq.gz, .fq.gz) will be silently ignored.

6. Run the pipeline

# Full pipeline end-to-end
nextflow run main.nf -profile local --step complete

# Single step
nextflow run main.nf -profile local --step qc

# Resume an interrupted run
nextflow run main.nf -profile local --step complete -resume

Modules

All 30 modules respect task.cpus and task.memory from conf/base.config unless they override with fixed values (RepeatMasker: 4 CPUs / 8 GB).

Phase 1 — QC and alignment
QCFASTQCmodules/fastqc.nf

Runs FastQC on each sample's read pair in parallel. HTML reports and zip archives are published per sample; zips are collected by MULTIQC.

Inputs

  • sample_id (val)
  • reads [R1, R2] (path)

Outputs

  • *.html (per sample)
  • *.zip (collected -> MULTIQC)
QCMULTIQCmodules/multiqc.nf

Aggregates all FastQC zip files into a single HTML report. In complete mode its report output acts as a gate that holds alignment back until QC completes.

Inputs

  • fastqc_zips (collected)

Outputs

  • multiqc_report.html
  • multiqc_report_data/
IndexBWA_INDEXmodules/bwa_index.nf

Builds a BWA-MEM2 index from the reference FASTA and permanently saves it to reference/bwa_index/. Skipped automatically on subsequent runs if that folder exists.

IndexBOWTIE2_INDEXmodules/bowtie2_index.nf

Builds a Bowtie2 index and saves it to reference/bowtie2_index/. Used for the optional align_bowtie step; PAV_ALIGN builds its own temporary index against the pan-gene FASTA.

AlignBWA_ALIGN_AND_SORTmodules/bwa_align.nf

Aligns paired reads with bwa-mem2 mem piped directly into samtools sort to avoid writing intermediate SAM files, then indexes the BAM. Read group tags are generated from the sample ID. A qc_done gate prevents alignment starting before MultiQC finishes in complete mode.

Inputs

  • sample_id + reads
  • reference (path)
  • bwa index files
  • qc_done (gate val)

Outputs

  • {sample}.sorted.bam + .bai
  • {sample}.alignment.log
StatsALIGNMENT_STATSmodules/alignment_stats.nf

Runs four samtools commands per BAM. Acts as a passthrough — the BAM tuple is re-emitted unchanged via the bam channel so QUALIMAP and EXTRACT_UNMAPPED_READS can chain from it without redundant disk reads.

Inputs

  • sample_id + bam + bai

Outputs

  • .flagstat.txt
  • .stats.txt
  • .coverage.txt
  • .idxstats.txt
  • bam (passthrough emit)
StatsQUALIMAPmodules/qualimap.nf

Runs qualimap bamqc with chromosome-limit painting and multi-thread support. Java heap size is derived from task.memory.toGiga() — ensure mem_per_task is set high enough in base.config.

Phase 2 — Assembly
ExtractEXTRACT_UNMAPPED_READSmodules/extract_unmapped.nf

Extracts three categories of unmapped reads using samtools flag filters, merges all three BAMs, then name-sorts the result. Name-sorting is mandatory before samtools fastq so paired reads are adjacent.

ScenarioFlagsDescription
Both unmapped-f 12 -F 256Read and mate both failed to align
Read unmapped, mate mapped-f 4 -F 264This read unaligned; its mate is placed
Mate unmapped, read mapped-f 8 -F 260This read placed; mate is unaligned
ExtractCONVERT_TO_FASTQmodules/convert_fastq.nf

Converts name-sorted unmapped BAM to paired gzipped FASTQ via samtools fastq. Secondary and supplementary alignments excluded (-F 0x900). Read suffixes /1 and /2 added (-N) as required by MaSuRCA.

PoolMERGE_FASTQmodules/merge_fastq.nf

Concatenates all per-sample unmapped FASTQs into a single pooled_R1.fastq.gz / pooled_R2.fastq.gz. Pooling across samples is the key pangenome step — it lets the assembler build contigs from novel content shared or unique across the cohort.

AssembleMASURCA_ASSEMBLYmodules/masurca_assembly.nf

Runs MaSuRCA with a dynamically generated config file. Key parameters (editable inline):

ParameterCurrent valueMeaning
PE insert mean / SD400 / 140 bpLibrary insert size — adjust to match your library
JF_SIZE1,500,000,000Jellyfish hash size — increase for large/repetitive genomes
CLOSE_GAPS1Attempt gap closure post-assembly
cgwErrorRate0.15Contig graph error tolerance

The module searches multiple possible output paths to accommodate different MaSuRCA versions. Assembly statistics (N50, total length, contig count) are computed with pure awk.

AssembleCOMBINE_CONTIGSmodules/masurca_assembly.nf

Only used in per-sample assembly mode. Concatenates all per-sample primary FASTAs into combined_contigs.fasta. Fixed at 1 CPU / 4 GB.

Phase 3 — Contamination removal
ContaminationBLAST_NTmodules/blast_nt.nf

BLASTn assembled contigs against NCBI nt using -remote (no local database required). Outputs a header-annotated TSV consumed by FILTER_BLAST. Parameters: evalue 1e-5, max_target_seqs 5.

Remote BLAST can be slow for large assemblies. Consider installing a local nt database and removing -remote from the blastn command in the module script.
ContaminationFILTER_BLASTmodules/blast_filter.nf

Multi-step filtering pipeline. Tunable inline variables at the top of the script:

VariableDefaultWhat to change
MIN_PIDENT80Minimum % identity to retain a hit
MIN_QCOVS50Minimum query coverage
MAX_EVALUE1e-5Maximum e-value
PLANT_TAXIDS"33090,3827"Allowed taxids (Viridiplantae + chickpea) — add yours if different
TAXDUMP_DIR$HOME/ncbi_taxdumpLocal NCBI taxdump path for taxonkit

Pipeline: quality filter -> best hit per contig -> plant vs non-plant split by staxid -> taxonkit lineage for non-plant taxids.

ContaminationREMOVE_CONTAMINANTSmodules/blast_remove.nf

Removes non-plant contigs identified by FILTER_BLAST. Produces clean_assembly.fasta (kept) and removed_contigs.fasta (discarded). Set DROP_NO_HIT=1 inline to also remove contigs with no BLAST hit at all (default: kept).

ContaminationFCS_SCREENmodules/fcs_screen.nf

Runs NCBI FCS-GX (fcs.py screen genome) against a local GX database. You must edit GXDB_DIR and TAXID inside the module script before running this step.

Inputs

  • assembly_fasta (path)

Outputs

  • fcs_screen.taxonomy.rpt
  • fcs_screen.fcs_gx_report.txt
ContaminationFCS_CLEANmodules/fcs_clean.nf

Applies the FCS-GX action report via fcs.py clean genome. Produces fcs_clean.fasta (clean contigs) and fcs_contam.fasta (removed contaminants).

Phase 4 — Repeat annotation
RepeatsEDTA_ANNOTATEmodules/edta_annotate.nf

Full EDTA TE annotation (--step all --anno 1 --sensitive 1 --species others). All outputs are collected under results/EDTA/EDTA_{basename}/. This step is optional — RepeatMasker GFF is used as the default repeat source for downstream gene filtering. To switch, uncomment the EDTA line in the repeat_gene_filter block of main.nf.

RepeatsREPEATMASKERmodules/repeatmasker.nf

Soft-masks repeats with RepeatMasker -species chickpea -xsmall -gff. Soft-masking (lowercase) is used rather than hard-masking (N) to preserve sequence for gene prediction. Fixed at 4 CPUs / 8 GB. Change -species inside the script if your organism is different. Outputs: *.masked (for BRAKER), *.out.gff (for REPEAT_GENE_FILTER).

RepeatsPANGENOME_MERGEmodules/pangenome_merge.nf

Concatenates the reference genome FASTA with RepeatMasker-masked novel contigs to produce pangenome.fasta. Stats file reports reference contigs, novel contigs, total contigs, and total assembly length.

Inputs

  • masked_contigs (path)
  • reference_fasta (path)

Outputs

  • pangenome.fasta
  • merge_stats.txt
Phase 5 — Gene prediction and filtering
PredictionBRAKERmodules/braker.nf

Runs BRAKER3 (braker.pl --prot_seq --softmasking) on the RepeatMasker-masked assembly using the protein hints file from protein_hints/. All BRAKER outputs are published to results/gene_prediction/. Key outputs consumed downstream: braker.gtf (gene models) and braker.aa (predicted proteins).

Gene filterCDHIT_FILTERmodules/cdhit_filter.nf

Clusters BRAKER predicted proteins at 95% identity (-c 0.95 -n 5 -M 0) to remove redundant isoforms or duplicated predictions. Outputs non-redundant proteins and the cluster file.

Inputs

  • braker.aa (path)

Outputs

  • cdhit_nr_proteins.fa
  • cdhit_nr_proteins.fa.clstr
Gene filterREPEAT_GENE_FILTERmodules/repeat_gene_filter.nf

Uses bedtools intersect to find gene models where more than 30% of the gene body overlaps RepeatMasker annotations, then removes them from the GTF. The overlap threshold is set inline in the awk filtering step. By default uses RepeatMasker GFF; to use EDTA output instead, uncomment the EDTA line in main.nf.

Inputs

  • braker_gtf (path)
  • repeat_gff (path)

Outputs

  • filtered_braker.gtf
  • genes_repeat_overlap.tsv
  • genes_to_remove.txt
Gene filterEXTRACT_FILTERED_GENESmodules/extract_filtered_genes.nf

Extracts nucleotide sequences for filtered gene models using gffread -w against the masked genome. Produces filtered_genes.fa for reference similarity filtering in the next step.

Gene filterREF_SIM_FILTERmodules/ref_sim_filter.nf

BLASTn filtered genes against the reference genome. Genes with >=80% identity AND >=80% query coverage are considered reference-like and removed using seqkit grep -v. Only genuinely novel genes are retained in ref_similarity_retained.fa.

Inputs

  • filtered_genes.fa (path)
  • reference_fasta (path)

Outputs

  • ref_similarity_retained.fa
  • ref_similarity_hits.tsv
  • ref_similarity_remove.txt
  • ref_similarity_stats.txt
Gene filterBUILD_PAN_GENE_SETmodules/build_pan_gene_set.nf

Concatenates cds_from_genomic.fna (reference gene set) with ref_similarity_retained.fa (novel genes) to produce the final pan_genes.fa. This catalogue is the input to the entire PAV analysis phase.

Inputs

  • cds_from_genomic.fna
  • ref_similarity_retained.fa

Outputs

  • pan_genes.fa
  • pan_genes_stats.txt
Phase 6 — PAV analysis
PAVPAV_ALIGNmodules/pav_align.nf

Builds a Bowtie2 index of pan_genes.fa then aligns each sample's raw reads against it using --no-mixed --local. Produces a sorted, indexed BAM per sample for coverage-based presence/absence calling.

Inputs

  • sample_id + R1 + R2
  • pan_genes.fa (path)

Outputs

  • {sample}.sorted.bam + .bai
  • {sample}.pav_align.log
PAVPAV_CALLmodules/pav_call.nf

Runs samtools coverage per gene per sample and applies presence/absence thresholds inline in an awk block. A gene is called present if at least 80% of its bases are covered at a mean depth of at least 3x. Adjust these thresholds in the awk script if needed.

Inputs

  • sample_id + bam
  • pan_genes.fa (path)

Outputs

  • {sample}.gene_coverage.tsv
  • {sample}.presence_absence.tsv
PAVPAV_CLASSIFYmodules/pav_classify.nf

Python3 + pandas script that outer-joins all per-sample presence/absence tables into a gene x sample matrix and classifies each gene. Classification thresholds:

ClassCriteria
corePresent in >=97% of samples
soft_corePresent in 90-97% of samples
shellPresent in 15-90% of samples
cloudPresent in <15% of samples (but in more than 1)
privatePresent in exactly 1 sample

Inputs

  • *.presence_absence.tsv (collected)

Outputs

  • pav_presence_absence_matrix.tsv
  • pav_gene_classes.tsv

Troubleshooting

Startup errors

Error messageCause and fix
No reference genome FASTA found in: ./referenceNo .fasta or .fa file in reference/. Note: .fna is not accepted for the genome FASTA.

No reads discovered

The pipeline accepts *_{R1,R2}.fastq.gz and *_{1,2}.fastq.gz. To support additional naming conventions, add patterns to the glob list in main.nf:

reads_ch = Channel.fromFilePairs([
    "${params.samples_dir}/**/*_{R1,R2}.fastq.gz",
    "${params.samples_dir}/**/*_{1,2}.fastq.gz",
    "${params.samples_dir}/**/*_R1_001.fastq.gz"  // add your pattern here
])

MaSuRCA fails or produces no output

Check results/logs/assembly/{id}_masurca.log.

SymptomLikely cause
assemble.sh not generatedMaSuRCA config is malformed or insert size (400 +/-140) does not match your library. Edit PE= in masurca_assembly.nf.
No primary FASTA locatedMaSuRCA version outputs to an unexpected path. The module tries several known paths; add the actual path to the search list if yours differs.
Very few contigsToo few unmapped reads. Check pool_stats.txt — low counts mean most reads mapped to the reference, leaving little to assemble.
Out of memoryIncrease mem_per_task in base.config and increase JF_SIZE for large or repetitive genomes.

BLAST_NT is very slow

Remote BLAST (-remote) can take many hours for large assemblies. Consider: (1) running during off-peak hours, (2) installing a local nt database and removing -remote from the blastn command in blast_nt.nf, or (3) splitting the assembly and running chunks in parallel.

FCS-GX errors

The most common cause is an incorrect or inaccessible GXDB_DIR. Verify the path contains all.gxi, all.gxs, and all other GX database files. Also confirm TAXID is set to your organism's NCBI taxid.

BRAKER fails or produces no gene models

Check results/logs/gene_prediction/braker.log. Common causes: AUGUSTUS config directory not set in environment, GeneMark-ETP licence expired, or the masked genome has too many Ns / too little unmasked sequence for training. Ensure all BRAKER3 dependencies (AUGUSTUS, GeneMark-ETP, DIAMOND, SPALN) are correctly installed and configured.

PAV matrix is all zeros or missing samples

Verify that pav_call produced .presence_absence.tsv files for all samples in results/pav/calls/. If files are missing, rerun pav_align and pav_call. Very low-coverage samples may have all genes called absent — check read counts in pav_align logs.

Pipeline resumes incorrectly

# Force a clean re-run by removing the Nextflow cache
rm -rf work/

# Or omit -resume for this run only
nextflow run main.nf -profile local --step complete
Warning: Deleting work/ means every step reruns from scratch. This can take many hours for compute-heavy steps like BLAST, EDTA, and BRAKER.

Reading execution reports

Every run writes three timestamped files to results/reports/: an HTML execution report, a timeline, and a trace. The trace lists per-task CPU time, wall time, and peak memory — the best starting point when diagnosing a slow or failed step.
